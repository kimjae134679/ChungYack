## 민간/사용자 제공 자료 기록 규칙

- 공식 공고문/기관 신청화면 캡처: 해당 회차 근거로 기록하되 화면 표기를 그대로 보존.
- 민간 집계/SNS/Zibble/유튜브: 후보 발견용. 공식 공고·공급표·임대조건표 검증 전 확정값으로 사용 금지.
- 민간 화면의 `월세`, `내가 준비할 금액` 표기는 화면표시값으로만 저장하고 공식 보증금 전환값으로 임의 해석하지 않는다.

## 상태 변경 기록 규칙

- `관심` → 관심·검토
- `넣는 중 / 넣자` → 신청 진행중 또는 신청예정
- `신청했어 / 넣었어` → 신청완료
- `결과 봐야 함` → 결과확인 필요
- `예비 ○번` → 예비
- `서류 냈어 / 서류 대상` → 서류
- `계약했어` → 계약·입주
- `보류` → 보류
- `패스 / 넘기자 / 제외` → 패스
- `탈락` → 종료/탈락

공식 발표시각이 경과했지만 개인 결과가 확인되지 않은 신청건은 결과확인 필요/서류대상 확인 긴급으로 승격하되 개인 결과를 임의 추정하지 않는다.

## Supabase 개인상태 선조회 강제 규칙

- 매 실행마다 공식 공고 검색 전에 Supabase `public.chungyack_client_state`를 먼저 조회한다.
- 최근 갱신 행 중 `state.tracking`이 실제로 존재하는 실사용 행을 우선한다.
- `state.tracking`의 `신청완료/예비/서류/계약/입주` 상태를 신규 행동 알림보다 우선한다.
- `state.savedOpportunities`는 찜, `state.hiddenOpportunities`는 숨김 의사로 사용한다.
- 이 원장은 폴백/스냅샷이며 최신 Supabase와 충돌하면 최신 Supabase를 우선한다.
- 공개 라이브 JSON에는 개인 상태를 복사하지 않는다.
- 세부 실행 절차는 `docs/PERSONAL_STATE_PREFLIGHT.md`를 반드시 함께 적용한다.
